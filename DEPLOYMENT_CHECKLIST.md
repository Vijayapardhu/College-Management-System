### Manual Steps Required

#### 1. Remove Duplicate Directory (if needed)
If `student-management-using-django/` directory exists:
```bash
# On Windows PowerShell:
Remove-Item -Recurse -Force "student-management-using-django"

# Or manually delete via File Explorer
```

#### 2. Commit and Push to GitHub
```bash
git add .
git commit -m "Prepare for Render deployment"
git push origin main
```

#### 3. Deploy to Render
1. Sign up/Login to Render.com
2. Connect GitHub repository
3. Create PostgreSQL database
4. Create Web Service
5. Configure environment variables (see RENDER_DEPLOYMENT.md)
6. Deploy!

## 📝 Environment Variables to Set in Render

```
DEBUG=False
SECRET_KEY=(auto-generated by Render)
DATABASE_URL=(auto-set when database is linked)
ALLOWED_HOSTS=your-app-name.onrender.com
CSRF_TRUSTED_ORIGINS=https://your-app-name.onrender.com

# Optional: Email Configuration
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_HOST_USER=your-email@gmail.com
EMAIL_HOST_PASSWORD=your-app-password
EMAIL_USE_TLS=True

# Optional: Supabase Storage
SUPABASE_URL=your-supabase-url
SUPABASE_KEY=your-supabase-key
SUPABASE_BUCKET=media
```

## 🚨 Important Notes

1. **Database**: Render PostgreSQL will automatically set `DATABASE_URL`
2. **Static Files**: WhiteNoise handles static files in production
3. **Media Files**: Use Supabase or Render Persistent Disk
4. **First Deploy**: Run migrations via Render Shell after deployment
5. **Superuser**: Create via `python manage.py createsuperuser` in Render Shell
